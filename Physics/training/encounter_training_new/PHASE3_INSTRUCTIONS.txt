=============================================
STEP 7: TRAIN THE V5 MODEL
=============================================

python -B train_pair_correction_v5.py ^
    --data encounter_data_zone3_phase3.npz ^
    --epochs 5000 ^
    --hidden 128 ^
    --output pair_correction_nn_v5.pt

(On Windows use ^ for line continuation, or run as one line.)

Expected runtime: ~10-20 min with GPU (CUDA), ~60 min CPU-only.

KEY THINGS TO CHECK in training output:
  1. Convergence: val loss should decrease steadily. If it plateaus early
     (before epoch 2000), try --lr 3e-4 on a second run.
  2. Per-dt recede bias table:
     - Phase 3 target: |rec_pred - rec_true| < 0.03 at all dts
     - Phase 2 had bias of ~0.035 at dt=0.04. If still present, add more
       strong_recede data and retrain.
  3. Fixed-state probe table:
     - dt=0.05-0.10 approach should be > 1.05 (not the 0.38 seen in v4)
     - If approach at large dt is still < 0.50, the probe_fix data didn't
       reach that region -- generate 2 more probe_fix batches and retrain.
  4. app_pred > rec_pred for ALL 6 dt groups (was 8/8 in v4, same target here).

  Find the PairCorrectionNNv4 class (or PairCorrectionNN class) in diagnostic_v4.py.

      def forward_raw(self, x):
          x_norm = (x - self.input_mean) / (self.input_std + 1e-8)
          return self.net(x_norm).squeeze(-1) + self.skip(x_norm).squeeze(-1)

=============================================
IF SOMETHING GOES WRONG
=============================================

Problem: Generation is very slow (taking >10 min per batch of 100)
Fix: This happens when the IC rejection rate is very high. Add --verbose_attempts
     to see what is being rejected. For probe_fix mode at large dt, the IAS15
     timeout can slow things. Try --timeout 30.

Problem: merge_encounter_shards.py fails with "missing fields" error
Fix: Check that all three generator modes output the same 12 fields. Run:
     python -c "import numpy as np; d=np.load('encounter_shards/...npz'); print(d.files)"
     on one shard of each mode.

Problem: Training loss doesn't decrease after epoch 1000
Fix: Try --lr 5e-4 or --lr 3e-4. The wider hidden=128 model sometimes needs
     a slightly lower initial learning rate.

Problem: Recede bias still > 0.05 after training
Fix: Generate 3 more strong_recede batches for the problem dt (likely dt=0.04)
     and retrain. The recede correction at dt=0.04 (c~0.79-0.83) is the hardest
     target in the dataset.
